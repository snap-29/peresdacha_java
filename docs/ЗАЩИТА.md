Читайте код в этом порядке: model → repository → dto → service → controller → security.

## Web MVC

@PathVariable — часть пути `/tasks/12`; @RequestParam — query-параметр `?status=NEW`.
201 означает создание ресурса; 204 означает успешное удаление без тела; 404 — ресурса нет.
@RequestBody читает JSON через HttpMessageConverter; без него DTO обычно связывается
с параметрами запроса, а не JSON. @ControllerAdvice устраняет повторение try/catch.
@RestController сочетает @Controller и @ResponseBody; обычный @Controller возвращает
имя HTML-шаблона. DispatcherServlet принимает запрос и выбирает handler.
Content negotiation учитывает Accept и доступные converters (Jackson здесь пишет JSON).
@Primary нужен при конкурирующих реализациях интерфейса; в конечном проекте один
JPA-репозиторий, InMemory-реализации нет, поэтому конфликта выбора нет.

## JPA

Контроллер вызывает сервис и не зависит от SQL или способа хранения. Здесь исходный
контроллер не приложен, поэтому историческое равенство файлов не заявляется.
Конструктор без аргументов требуется JPA для создания сущности. Enum STRING хранит
имя, ORDINAL — позицию: перестановка enum испортит смысл старых чисел.
JPQL использует Java-классы и поля: `select t from Task t where t.status = :status`.
SQL использует таблицы и столбцы: `select * from tasks where status = 'NEW'`.
Derived query `findByStatusAndPriority` генерирует условия по обоим полям.
Page содержит content, общее число записей/страниц и сведения о текущей странице.
create-drop создаёт схему при старте и удаляет при остановке, данные не сохраняются.
show-sql показывает выполняемые select/insert/update/delete; format_sql делает их читаемыми.
DTO ограничивает контракт API и не раскрывает owner.password или ленивые JPA-связи.

## Транзакции

A в ACID — атомарность: изменения выполняются целиком или откатываются.
По умолчанию RuntimeException/Error вызывают rollback, checked IOException — нет.
`rollbackFor=Exception.class` включает откат для checked исключений.
readOnly — подсказка менеджеру/JPA для чтения и оптимизации; это не универсальный запрет
SQL-записи на уровне любой БД. REQUIRED участвует в текущей транзакции,
REQUIRES_NEW приостанавливает текущую и создаёт независимую. Аудит попыток поэтому
переживает откат основной операции. Вызов `this.method()` не проходит через Spring-прокси.
@DataJpaTest по умолчанию откатывает тест; для проверки настоящего commit/rollback
в TransactionBehaviorTest внешняя транзакция отключена через NOT_SUPPORTED.

## Миграции

Flyway применяет V1, V2, V3 по очереди и хранит checksum в истории. Старую применённую
миграцию не меняют: нужно написать следующую. Liquibase использует changeset с
идентификатором, автором и файлом; в SQL можно описать rollback.
`ddl-auto=validate` ничего не создаёт — только сверяет схему после миграций.
Для реального восстановления схемы нужно сбросить и таблицы, и историю на отдельной
учебной базе; удаление только tasks при сохранённой истории не заставляет повторить V1.
Выбор Flyway здесь обусловлен небольшим числом простых SQL-изменений.

## JUnit и Mockito

Unit-тест запускает обычный Java-объект с моками; integration-тест проверяет взаимодействие
с настоящими Spring/JPA/HTTP-компонентами. @Mock создаёт замену зависимости,
@InjectMocks передаёт моки тестируемому объекту. MockitoExtension инициализирует их.
AAA: сначала when и данные, затем вызов сервиса, затем assertThat/verify.
`verify(repository).save(any())` проверяет вызов, а не реальное сохранение в БД.
`assertThatThrownBy` проверяет тип и сообщение исключения. `never()` или
`verifyNoInteractions` подтверждают отсутствие вызовов. Constructor injection
позволяет создавать сервис без Spring и явно видеть зависимости.

## Security

Сессия хранит состояние на сервере; JWT содержит подписанные claims и позволяет
проверять запрос без сессии. Подпись не шифрует payload — пароль туда не помещают.
FilterChainProxy выбирает цепочку: API → JWT/STATELESS, браузер → form-login/сессия.
JwtAuthFilter читает Bearer, проверяет подпись и срок, загружает UserDetails,
устанавливает Authentication, вызывает chain.doFilter. Ошибка токена даёт 401 JSON.
BCrypt — адаптивное хеширование с солью; PasswordEncoder.matches проверяет пароль.
@EnableMethodSecurity активирует @PreAuthorize; без него аннотация не ограничивает доступ.
hasRole('ADMIN') эквивалентен hasAuthority('ROLE_ADMIN').
401 — нет корректной аутентификации, 403 — пользователь известен, но права не позволяют.
ControllerAdvice обрабатывает ошибки контроллеров/сервисов; ошибки security-фильтров
обрабатывают AuthenticationEntryPoint и AccessDeniedHandler.
@WithMockUser создаёт Authentication для проверки ролей, JWT не генерирует и парсер
не проверяет. В @WebMvcTest моки JWT/UserDetailsService позволяют поднять только
HTTP-слой; реальные токены дополнительно проверяются в AuthFlowIntegrationTest.
В данном проекте реальный JwtAuthFilter остаётся в MVC-тестах: мокируются его зависимости,
поскольку пустой mock-фильтр без doFilter пропустил бы тестируемый контроллер целиком.

Current user можно получить из SecurityContextHolder или через @AuthenticationPrincipal.
Использован второй вариант: actor явно передаётся сервису. Owner тестируется через
ArgumentCaptor, а чужой пользователь проверяется через AccessDeniedException.
isOwner(id,email) возвращает результат проверки owner и может использоваться в SpEL
`@taskService.isOwner(#id, authentication.name)`; фактическая проверка доступа здесь
в сервисе позволяет вернуть 404 для отсутствующего id.
Refresh нужен для продления короткого access; ротация меняет refresh, logout удаляет их
из БД. Уже выданный access не отзывается автоматически.

## Thymeleaf

Model передаёт данные в шаблон. th:object задаёт form-backing bean,
th:field связывает HTML-поле с его свойством. BindingResult хранит ошибки @Valid,
th:errors отображает их; он должен идти сразу после DTO-параметра.
Redirect после POST реализует Post-Redirect-Get и предотвращает повторное создание при F5.
th:replace заменяет элемент фрагментом, th:insert вставляет фрагмент внутрь элемента.
sec:authorize проверяет права текущей Authentication, th:if — произвольное выражение.
Скрытие HTML-кнопки само по себе не защищает endpoint: нужна серверная проверка.
th:action для POST-форм включает скрытый CSRF-токен при интеграции со Spring Security.
В API CSRF отключён, потому что Bearer передаётся явно; у браузерных сессий CSRF включён.

## Docker

Образ — набор слоёв/инструкций; контейнер — запущенный экземпляр образа.
Два контейнера одного образа можно запустить с разными именами и портами host.
Multi-stage оставляет JDK/Maven в builder и только JRE/JAR в runtime.
`postgres` — имя сервиса в Docker-сети; localhost внутри app обозначает сам app.
depends_on с service_healthy ждёт успешный healthcheck БД, а не просто создания контейнера.
`down` удаляет контейнеры/сеть, `down -v` дополнительно удаляет данные volume.
.env задаёт локальные секреты, его не включают в Git/образ.
Non-root уменьшает полномочия процесса. EXPOSE документирует порт, ports/-p публикует его.
Для диагностики сначала смотрят `docker compose logs app`, затем `ps`, затем SQL в БД.
